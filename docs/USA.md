# USA version (RPBE01)

The project builds two versions from the same sources:

| Version | Game ID | `main.dol` SHA-1 |
|---|---|---|
| PAL, revision 0 (main target) | `RPBP01` | `ffcd539d239722b8bb27e45c9ad4aacc818c8933` |
| USA, revision 0 | `RPBE01` | `b8d70d7500497dc74bed4223260f3c0ac8540c83` |

Build the USA version with:

```sh
python configure.py --version RPBE01
ninja
```

Put the disc image in `orig/RPBE01/` first.

## How the two versions differ

The USA `main.dol` is an earlier build than the PAL one. It has about 14 KiB more code and about 112 KiB less data. About 94.5 % of functions have the same size in both versions. The rest differ, mostly in the framework code at the start of `.text` (`0x8000B000`–`0x80025000`), and in a handful of game units elsewhere.

Function and data names come from the PAL config even where they encode a PAL address (`fn_80006A88` is at a different address in the USA build). This lets the same source file compile and diff against both versions. A function that exists only in the USA build keeps the name dtk gave it; the `_RPBE01` suffix marks the rare case where that name was already used for a different PAL symbol.

Use `#if VERSION_RPBE01` (or `BUILD_VERSION == 1`) in source for code that differs between the versions.

## Config files

| File | Contents |
|---|---|
| `config/RPBE01/seed_symbols.txt` | Symbols dtk needs before it can analyze the USA DOL (the size of one jump table indexed by a `u8` with no bounds check) |
| `config/RPBE01/symbols.txt`, `splits.txt` | Generated by `tools/port_version.py` |
| `config/RPBE01/port.log` | Every symbol and split range the port could not place, and why |
| `config/RPBE01/linked.txt` | Finished units verified to match the USA build. Written by `tools/verify_linked.py` |

Do not edit the generated files by hand. Fix the PAL config or `seed_symbols.txt` and port again.

## Porting the config again

When the PAL config changes, port it again:

```sh
python configure.py --version RPBE01 && ninja    # builds the objects the port refines from
python tools/port_version.py --src RPBP01 --dst RPBE01
python tools/verify_linked.py --version RPBE01
```

`port_version.py` maps PAL symbols to USA addresses in three passes.

1. dtk analyzes the USA DOL. Within each section, the PAL and USA symbol lists are aligned by size. A run of equal sizes is an anchor with a fixed address delta. A symbol between two anchors that agree on the delta is moved by that delta. Where both lists have the same number of symbols between anchors but different sizes, the code changed, and symbols are paired in order.
2. Each unit's `__sinit` is found through `.ctors`, which has the same layout in both versions.
3. If a USA build exists, the relocations of every function that is the same size in the compiled object and in the object split from the USA DOL are paired. This places the data each unit references, and with it the unit's data sections. A hint never overrides a placement from step 1, and weak symbols (inline functions emitted in every unit) are ignored.

Unit boundaries inside code that changed between versions are estimated, and logged in `port.log`. They only affect how those units diff, not the build: the build always matches, because only the units in `linked.txt` are linked and each one is verified.

`verify_linked.py` links each finished PAL unit into the USA build on its own and keeps the units for which `main.dol` still matches.
